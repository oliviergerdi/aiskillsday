# PRD 0001 Implementation Plan: review ledger, configurations, rerun, sign-off

> **For agentic workers:** execute with superpowers:executing-plans (native: one session builds, Gerdi runs tests and reviews). Steps use `- [ ]`. Claude cannot run code: every "Run" step is Gerdi's.

**Goal:** accept/reject findings in the web UI with decisions that carry across runs, save and rerun configurations against a baseline, and give the manager a sign-off page.

**Architecture:** all review logic in a new `nparity/review.py` (ledger, review state, verdict, baseline compare). Configurations are a web feature in `app/web/configs.py`. Routes and templates only format. Nothing in mapping, triage or thresholds changes.

**Spec:** `docs/prd/0001-design.md` (approved 14:50).

## Global constraints

- Ledger: one entry per `(scope, key)`, exact keys only, never wildcards, never written by the model.
- Review state is computed at view time and never stored in a run file.
- Every write route uses the existing `local_run_request` guard.
- Tests are key-free. Ledger and comparisons paths come from `app.state.ledger_path` and `app.state.comparisons_dir`, which tests point at `tmp_path` (as `runs_dir` today).
- UX-2 is already in (verdict line, empty state, no dead buttons). Build on it, don't revert it.

## Review focus

1. **Key drift:** the same toy difference in two separate runs must produce the same key. → Task 1
2. **A reject that doesn't block:** a rejected finding the model called intended must count as open. → Task 1
3. **Baseline picks the run itself, or another configuration's run.** → Task 2
4. **Decisions leaking across scopes:** a decision on `toy` must not apply to a `petstore` run with the same key. → Task 1
5. **Non-local write:** a POST from a non-localhost client is refused. → Task 6

### Task 1: Ledger and review state

**Files:** Create `nparity/review.py`, `accepted.yaml` (`entries: []`), `tests/test_review.py`.

**Produces:**
```python
def finding_key(f: Finding) -> str          # "<endpoint> -> <new_endpoint or '-'> | <path> | <kind>"
def scope_of(run: Run) -> str               # run.config["config"] or "<old> -> <new>"

class Entry(BaseModel):
    scope: str; key: str; endpoint: str; path: str; kind: str
    decision: Literal["accept", "reject"]; by: str; at: datetime; note: str = ""
    run: str; model_label: str | None; model_p: float | None

class Ledger:
    path: Path
    @classmethod
    def load(cls, path: Path) -> "Ledger"                 # missing file = empty
    def get(self, scope: str, key: str) -> Entry | None
    def record(self, run: Run, f: Finding, decision: str, by: str, note: str = "") -> Entry   # replaces, saves
    def remove(self, scope: str, key: str) -> bool        # saves
    def in_scope(self, scope: str) -> list[Entry]

ReviewState = Literal["needs_review", "intended_model", "accepted", "rejected"]
def review_states(run: Run, ledger: Ledger) -> dict[str, tuple[ReviewState, Entry | None]]   # by finding id
def verdict(run: Run, ledger: Ledger) -> tuple[str, str]   # (text, css class reg|uns|int)
def stale(run: Run, ledger: Ledger) -> list[Entry]
```
State table and verdict text exactly as design "Review state". Writes under a module-level `threading.Lock`; file written with `yaml.safe_dump(..., sort_keys=False)`. `by` is stripped and must be non-empty (`ValueError`).

- [ ] Tests:
  - Review focus 1: two separate toy runs (`pipeline.run` with FakeBackend, as `tests/test_e2e.py`) give identical key sets.
  - `scope_of` with `config: toy` → `toy`; without → `http://testserver/v1 -> http://testserver/v2`.
  - `record` then `record` again on the same finding → one entry, latest decision; `remove` → gone; file round-trips.
  - Entry stores `model_label` and `model_p` from the finding.
  - State table row by row: shown → needs_review; unsure → needs_review; accepted → intended_model; any + accept → accepted; Review focus 2: accepted-by-model + reject → rejected and counted open.
  - Verdict on the toy run: no ledger → "4 open items: 0 confirmed regressions, 4 need review"; after accepting all 3 regressions and the unsure → "Ready to cut over"; errors count as open.
  - Review focus 4: an entry with scope `toy` doesn't affect a run whose scope is `petstore`.
  - `stale`: an entry whose key isn't in the run is returned.
  - Empty `by` → `ValueError`.
- [ ] Run `uv run pytest tests/test_review.py -q`: fail, implement, pass. Commit `feat(review): ledger and review state`.

### Task 2: Baseline compare

**Files:** Modify `nparity/review.py`, `tests/test_review.py`.

**Produces:**
```python
class Comparison(BaseModel):
    baseline_id: str
    status: dict[str, Literal["new", "unchanged"]]    # by finding id in the run
    resolved: list[Finding]                           # in baseline, not in run
    @property
    def counts(self) -> dict[str, int]                # new, unchanged, resolved

def compare(run: Run, baseline: Run) -> Comparison
def latest_baseline(run_or_scope: Run | str, runs: list[Run], before: datetime | None = None,
                    exclude: str | None = None) -> Run | None   # newest same-scope run, never `exclude`
```
